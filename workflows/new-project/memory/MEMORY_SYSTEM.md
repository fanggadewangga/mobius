# Mobius Project Memory System

Inspired by the APM Memory Bank — ensures project state is not lost even if agents change or context windows fill up.

## Memory Files

### SPEC.md — Product Specification
Generated by the Product Agent in Phase 02.
Must not be changed after Phase 03 starts unless there is an explicit scope change.
If there is a scope change → create `SPEC_AMENDMENT.md`, do not edit `SPEC.md` directly.

### IMPLEMENTATION_PLAN.md — Implementation Plan
Generated by the Engineer Lead in Phase 04.
Updated as each task is completed (mark [x] in the checklist).
No new tasks should be added without Engineer Lead approval.

### ADR/ — Architecture Decision Records
Every significant architectural decision → create a new ADR.
Format: `ADR-XXX-[kebab-case-title].md`
Do not modify Accepted ADRs.
If a change is needed → create a new ADR that Deprecates the old one.

### TASK_LOG.md — Task Execution Log
Updated by Workers after task completion.
Append-only — do not edit existing entries.

### PROGRESS.md — Phase Progress

## Handoff Protocol
If the agent's context window is nearly full:
1. Save all state to memory files.
2. Generate a Handoff Summary:
   ```
   HANDOFF SUMMARY
   Current phase: [X]
   Current task: [TASK-XXX]
   Progress: [X/Y tasks in this phase]
   Last decision: [Last decision made]
   Next action: [What the fresh agent should do]
   Read these files: [List of files the fresh agent needs to read]
   ```
3. The fresh agent reads the Handoff Summary + listed files.
4. Continue from the same point.
